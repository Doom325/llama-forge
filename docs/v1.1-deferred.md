# v1.1 Deferred work

Items intentionally deferred from v1.0 to a future v1.1 cut. Each
entry names the artifact, the reason it stayed out of v1.0, and the
follow-up scope it implies.

## Audit principal / task attribution

- **Site:** `InferenceEngineAdapter::audit_ctx` construction
  (`crates/llamaforge-adapters/src/inference_engine.rs:190–195`).
- **Status in v1.0:** `RequestorId("anonymous")` and `TaskTypeId("default")`
  are hardcoded; every persisted `RequestMetrics` row collapses onto the
  same `(requestor, task_type)` pair.
- **Rationale:** per-request principal/task attribution requires plumbing
  identity from the inbound request into the inference engine adapter,
  which the v1.0 request pipeline doesn't carry yet.
- **Follow-up:** thread requestor + task type through the dispatch path
  so `AuditContext` is built from the real request, and extend `audit.rs`
  to also set `effective_priority` and `prompt_tokens`.

## `ConfigOverlayStore`

- **Trait:** `llamaforge-metrics::traits::ConfigOverlayStore`
  (`crates/llamaforge-metrics/src/traits.rs:91`), sealed.
- **Status in v1.0:** trait defined; no production implementation.
- **Rationale:** the design doc (§2.8) explicitly scopes per-server
  runtime config overlays — A/B testing model parameters, gradual
  rollouts of decoding-tuning knobs — to v1.1. v1.0 supports
  whole-config writeback through `ConfigWriter`, which is sufficient
  for the supported workflows.
- **Follow-up:** wire a SQLite-backed impl that persists per-server
  overlays, expose a management API to write/clear them, and have the
  composition root read the overlay snapshot when constructing
  `ServerConfig` for spawn.
